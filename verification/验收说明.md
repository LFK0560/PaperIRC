## 公共服务器故障复现与修复验证

实测服务器 MOTD 第一个 `372` 数值回复结尾为 `CR CR LF`，旧帧读取器仅剥离最后一个 CR，随后解析器拒绝剩余 CR。旧 JAR 在注册后复现原报错；修复 JAR 完成注册和 24 行 MOTD。证书链由 Java 25 默认信任库接受，SAN 仅包含域名，未包含 IP 地址。按 IP 连接在注册前被主机名校验拒绝，报 `No subject alternative names matching IP address`，这是预期拒绝结果。服务端公布 `CASEMAPPING=ascii`、`NICKLEN=20`。

可在自己的服务上运行以下诊断，仅注册临时昵称、处理保活和退出，不执行 JOIN/PRIVMSG；临时昵称需未被占用：

```sh
/path/to/jdk-25/bin/java --class-path target/PaperIRC-1.0.1.jar \
  verification/IrcRegistrationProbe.java irc.example.invalid 6697 PIProbeTest
```

将 `irc.example.invalid` 替换为自己的证书域名。该验证覆盖公共 CA、主机名和真实注册协议；Linux 上运行的 Paper 实例及其目标频道权限、真人客户端聊天仍需按下方步骤验收。

## 实际 Paper 加载验证

`run_paper.py` 在新目录运行官方 Paper 26.3 build 178，加载实际构建的 JAR，连接独立 TLS 协议服务。使用从 JDK CA 库复制的专用测试信任库，额外加入该运行的测试 CA；不修改系统或生产信任库。

```sh
python3 verification/run_paper.py \
  --java-home /path/to/jdk-25 \
  --paper-jar /path/to/paper-26.3-178.jar \
  --accepted-eula-file /path/to/test-server/eula.txt
```

可选 `--cache-from /path/to/test-server` 只读复制 Paper 依赖以节省下载。测试仅绑定回环地址，正式环境不要套用其 offline-mode 或测试信任库参数。

脚本检查加载、无人在线唯一机器人、`!list` 返回 `0/20`、真实 TPS/MSPT/JVM 运行时间、`!help`、控制台指令注册、无效重载保留配置、有效重载、手动重连及停服 QUIT/连接关闭。成功结果保存到 `paper-result.json`，概要在 `paper-integration.log`，服务端日志在 `paper-smoke.log`。

本机模拟客户端库尚不支持 26.3。Linux 目标机、真人登录、游戏端权限及完整游戏聊天尚待实机验收，步骤如下。原始需求的所有关键核心路径已有上述协议/TLS 自动化覆盖，但自动化不能替代这些部署检查。

## 可重复的真实 ngIRCd 自动集成

安装/编译支持 TLS 的 ngIRCd 后运行：

```sh
python3 verification/run_ngircd.py \
  --java-home /path/to/jdk-25 \
  --ngircd /path/to/ngircd
```

脚本只创建新测试目录，使用独立证书、回环监听、32 个同 IP 名额和 32 字符昵称上限，不修改现有 ngIRCd 服务。开启认证 PING，验证插件正确回答 PONG。通过环境变量仅启用 `RealNgircdTest`；平时 `./mvnw verify` 会跳过这个需真实服务的测试。

执行结果在 `ngircd-integration.log`，服务器日志在 `ngircd-server.log`。该测试真实建立 20 个个人身份及机器人，还使用两个外部 IRC 测试客户端检查频道成员和发言。游戏侧用 `GamePort` 捕获投递；真人 Minecraft 客户端另按下面步骤验收。停用后通过 NAMES 确认只剩两个外部测试客户端，然后退出全部测试进程。

## 真实 ngIRCd / Linux / 游戏客户端验收

对负面测试，在专用测试环境设置较短超时便于复现；完成后恢复生产合理值。验证保存失败可以在专用实例使目录不可写，再修改设置：应明确报错，不能出现“已保存”；修复权限后再保存成功。坏文件测试先备份，停服制造无效 YAML 后启动，插件应保留原文件并拒绝覆盖。
